Java Environment Explained

15 October 2026

Java is more than a programming language. To develop and run Java applications, you need an environment that can compile your code, execute it and provide the libraries it depends on.

Coming from PHP, some concepts will feel familiar, but Java has important differences in its type system, memory management, concurrency model and runtime. Understanding these differences helps you write safer code and debug production issues.

The Big Picture

  • JDK (Java Development Kit) — development tools, including the compiler.
  • JRE (Java Runtime Environment) — the traditional set of components required to run Java applications.
  • JVM (Java Virtual Machine) — executes Java bytecode.
  • Bytecode — platform-independent instructions produced by the Java compiler.
  • Classpath — tells Java where to find classes and libraries.
  • JAVA_HOME — conventionally points to a JDK installation.
  • PATH — tells the operating system where to find executable commands.
  • Garbage collector — automatically reclaims memory occupied by unreachable objects.
  • JIT compiler — can compile frequently executed bytecode into native machine instructions at runtime.

How Java Code Runs

Java typically uses two main steps: compilation and execution. The compiler translates source code into bytecode, which a compatible JVM can execute. 

Java Source Code
    Main.java
        |
        | javac (compiler)
        v
Java Bytecode
    Main.class
        |
        | java (launcher)
        v
JVM
        |
        v
Program Execution

For example, create a file named Main.java:

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}

Compile the source file:

javac Main.java

This generates Main.class, containing Java bytecode.

Run the program:

java Main

Output:

Hello, Java!

Notice that you use java Main, not java Main.class. The launcher expects a class name when launching a class from the classpath.

JDK vs JRE vs JVM

JVM — Java Virtual Machine

The JVM is the runtime engine that loads and executes Java bytecode. It manages runtime operations such as class loading, memory allocation and garbage collection.

The JVM is platform-specific, even though Java bytecode is designed to be portable.

JRE — Java Runtime Environment

The JRE traditionally refers to the JVM together with the libraries and components required to run Java applications. It does not include development tools such as the Java compiler.

Modern Java distributions do not always offer a separate JRE download. Developers commonly install a JDK, which also contains the components needed to run Java applications.

JDK — Java Development Kit

The JDK is what developers normally install. It includes the Java runtime and tools for compiling, debugging and packaging Java applications.

Why Does Java Use Bytecode?

Bytecode sits between Java source code and the underlying machine. The compiler translates Java code into a standardized format that a compatible JVM can execute.

This is the foundation of Java's "Write Once, Run Anywhere" idea. Compatibility still depends on the Java version, available libraries and any platform-specific dependencies.

The JIT Compiler

The JVM can interpret bytecode and use a Just-In-Time (JIT) compiler to compile frequently executed code into native machine instructions at runtime.

The JVM can optimize code based on how the application actually behaves. This is one reason Java performance can improve after an application has been running for a while.

JAVA_HOME vs PATH

JAVA_HOME

JAVA_HOME conventionally points to the root directory of a JDK installation. 

JAVA_HOME=/path/to/jdk

For example:

JAVA_HOME=/usr/lib/jvm/jdk-21

Build tools, IDEs and other applications may use this variable to locate Java.

PATH

PATH is a list of directories that the operating system searches when you run a command. 

PATH=$JAVA_HOME/bin:$PATH

This is common Unix-like shell syntax. Windows uses different syntax for configuring environment variables.

Variable Purpose Example
JAVA_HOME Identify the JDK installation /usr/lib/jvm/jdk-21
PATH Locate executable commands $JAVA_HOME/bin

Setting JAVA_HOME does not automatically guarantee that the correct Java executable is used. PATH ordering and IDE or build-tool configuration also matter.

How to Check Your Java Installation

java -version
javac -version

Check command locations on Linux or macOS:

which java
which javac

On Windows:

where java
where javac

Check JAVA_HOME on Linux or macOS:

echo $JAVA_HOME

On Windows Command Prompt:

echo %JAVA_HOME%

If java works but javac is missing, the JDK may not be installed or its bin directory may not be available through PATH.

What Is the Classpath?

The classpath tells Java where to find compiled classes and JAR files required by an application. 

project/
 |
 +-- Main.class
 |
 +-- lib/
      |
      +-- library.jar

Linux or macOS:

java -cp ".:lib/library.jar" Main

Windows:

java -cp ".;lib/library.jar" Main

The current directory is represented by .. Unix-like systems separate classpath entries with a colon, while Windows uses a semicolon.

PATH helps the operating system locate executables. The classpath helps Java locate application classes and libraries. They solve different problems.

What Is a JAR File?

A JAR (Java Archive) packages compiled classes, resources and metadata into a single file. It uses the ZIP archive format. 

my-application.jar
 |
 +-- Main.class
 |
 +-- com/example/Service.class
 |
 +-- application.properties
 |
 +-- META-INF/MANIFEST.MF

A JAR can be launched with java -jar when it has the appropriate manifest and entry point. 

java -jar my-application.jar

Java's Type System

PHP supports type declarations, but Java uses a more extensive compile-time type system. Many type errors can be detected before the application runs. 

List<String> names = new ArrayList<>();

names.add("Nefeli");
// names.add(123); // Compile-time error

Java's generic collections specify the type of elements they accept. This improves type safety and reduces the need for manual casting.

Type Erasure

An important Java-specific detail is that generic type information is mostly erased at runtime. 

List<String> names = new ArrayList<>();
List<Integer> numbers = new ArrayList<>();

Although these lists have different generic types at compile time, their runtime class is generally the same: ArrayList.

This is called type erasure. It means you generally cannot check whether an arbitrary object is a List<String> at runtime.

Primitives vs Wrapper Classes

Java has primitive types such as int, long, double and boolean, alongside object wrappers such as Integer, Long, Double and Boolean. 

int count = 5;
Integer boxedCount = count;

List<Integer> counts = new ArrayList<>();
counts.add(5);

Generic collections use object types rather than primitive types. Java automatically converts between primitives and their wrappers through boxing and unboxing.

A primitive variable cannot be null, but a wrapper object can. Unboxing a null wrapper can throw a NullPointerException.

Object Equality: == vs equals()

This is one of the most important differences to understand when coming from PHP.

For Java objects, == compares references: it checks whether both variables refer to the same object. equals() can compare logical equality when the class implements it appropriately. 

String a = new String("hello");
String b = new String("hello");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true

In PHP, two strings with the same value compare equal using ===. In Java, use equals() when you want to compare the contents of ordinary objects such as strings.

equals() and hashCode()

Java hash-based collections, such as HashMap and HashSet, rely on both equals() and hashCode(). 

Map<Customer, String> customers = new HashMap<>();

If two objects are equal according to equals(), they must return the same hash code. Otherwise, hash-based collections may behave unexpectedly.

If you override equals(), you should normally override hashCode() consistently as well.

Java Passes Arguments by Value

Java always passes arguments by value, including when the argument is an object reference. 

class Customer {
    String name;
}

static void changeName(Customer customer) {
    customer.name = "Alex";
}

static void replaceCustomer(Customer customer) {
    customer = new Customer();
    customer.name = "New Customer";
}

Calling changeName() modifies the original object. Calling replaceCustomer() does not replace the caller's reference because the method only reassigns its local copy of that reference.

static, final and Immutability

static

A static member belongs to the class rather than to an individual instance. Static fields are shared by instances of the same loaded class. 

class Counter {
    static int total = 0;
}

final

A final variable can only be assigned once. For a reference, this prevents reassignment but does not automatically make the referenced object immutable. 

final List<String> names = new ArrayList<>();

names.add("Nefeli"); // Allowed
// names = new ArrayList<>(); // Not allowed

Records

Records provide a concise way to declare data-carrier classes. They automatically provide accessors, equals(), hashCode() and toString(). 

public record Money(long amount, String currency) {}

Money money = new Money(1000, "EUR");

System.out.println(money.amount());
System.out.println(money.currency());

Records are useful for DTOs and value-like data. They are shallowly immutable: a record containing a mutable object does not automatically make that object immutable.

Checked vs Unchecked Exceptions

Unlike PHP, Java distinguishes checked exceptions from unchecked exceptions. The compiler requires checked exceptions to be caught or declared in a method's signature. 

try {
    String content = Files.readString(Path.of("data.txt"));
} catch (IOException e) {
    System.err.println("Could not read file");
}
  • Checked exception: IOException.
  • Unchecked exception: NullPointerException.
  • Unchecked exception: IllegalArgumentException.

Checked exceptions are useful for some recoverable error conditions, but they can also add boilerplate. Understanding which exceptions an API throws is important when designing service boundaries.

Try-with-resources

Java provides try-with-resources to close resources automatically when execution leaves the block, including when an exception occurs. 

try (var reader = Files.newBufferedReader(path)) {
    String line = reader.readLine();
}

This works with resources that implement AutoCloseable, such as many file, stream and database resource types.

Heap, Stack and Garbage Collection

Java manages memory automatically, but understanding the JVM's memory model is important for debugging performance issues. 

Thread
 |
 +-- Stack
 |    |
 |    +-- Method calls
 |    +-- Local variables
 |    +-- Object references
 |
Heap
 |
 +-- Objects
 +-- Arrays
 +-- Collections
  • Stack: holds method execution frames and local execution state. Local primitive values and references may be stored in these frames.
  • Heap: where objects and arrays are generally allocated.
  • Garbage collector: reclaims memory used by objects that are no longer reachable.

You do not manually free ordinary Java objects, but memory leaks can still occur. For example, a static collection or an unbounded cache can retain objects that the application no longer needs.

A memory leak in Java often means unnecessary objects remain reachable, preventing the garbage collector from reclaiming them.

Threads and Concurrency

Java applications commonly use multiple threads within a single process. Threads can access shared objects, which means that concurrent operations can interfere with one another. 

class Counter {
    private int count = 0;

    void increment() {
        count++;
    }
}

If multiple threads call increment() simultaneously, some updates can be lost. The increment operation is not atomic.

synchronized

The synchronized keyword allows only one thread at a time to execute a synchronized block guarded by the same monitor. 

class Counter {
    private int count = 0;

    synchronized void increment() {
        count++;
    }
}

This protects increments made through this synchronized method on the same Counter instance. All access paths to shared state must follow a compatible synchronization strategy.

Atomic Classes

Java also provides atomic classes for common thread-safe operations. 

AtomicInteger counter = new AtomicInteger(0);

counter.incrementAndGet();

AtomicInteger makes this increment atomic. It does not automatically make a sequence of multiple operations atomic.

Thread Pools and Futures

Creating and managing threads manually is often unnecessary. ExecutorService manages task execution, while Future and CompletableFuture represent results that may become available later. 

ExecutorService executor =
    Executors.newFixedThreadPool(4);

try {
    Future<Integer> result =
        executor.submit(() -> 1 + 2);

    System.out.println(result.get());
} finally {
    executor.shutdown();
}

This is a simplified example. Production applications should consider task timeouts, cancellation, exception handling and appropriate executor sizing.

Virtual Threads

Virtual threads, permanently available since Java 21, are lightweight threads managed by the Java runtime. They can make applications with many blocking I/O tasks easier to structure. 

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> {
        System.out.println("Running in a virtual thread");
        return null;
    });
}

Virtual threads do not make CPU-intensive tasks execute faster by themselves. Database connection limits, synchronization and other resource constraints still matter.

Streams and Lambdas

Java Streams provide a declarative way to filter, transform and aggregate collections. Lambdas and method references make these operations concise. 

List<String> activeNames = customers.stream()
    .filter(Customer::isActive)
    .map(Customer::getName)
    .toList();

This filters active customers and extracts their names. Intermediate stream operations are generally lazy, and a stream is normally consumed only once.

Parallel streams are also available, but they should not be assumed to be faster. Parallel execution introduces overhead and can be inappropriate for blocking I/O or operations with shared mutable state.

Optional and Null Handling

Java references can be null. Optional provides an explicit way for APIs to represent a value that might be absent. 

Optional<Customer> customer =
    customerRepository.findById(id);

customer.ifPresent(this::sendNotification);

Other useful methods include:

  • map() — transform a present value.
  • orElse() — provide a fallback value, evaluated eagerly.
  • orElseGet() — provide a fallback through a lazily invoked supplier.
  • orElseThrow() — return the value or throw an exception.
String name = optionalName.orElse("Unknown");

String name = optionalName.orElseGet(
    () -> loadDefaultName()
);

Optional is commonly used as a return type for potentially absent results. It does not eliminate nulls everywhere, and calling methods on a null Optional still throws an exception.

Class Loading and Reflection

Java loads classes into the runtime dynamically through class loaders. Classes may be loaded when they are first needed, rather than all at application startup.

Reflection allows code to inspect classes, methods, fields and annotations at runtime. 

Class<?> type = Customer.class;

System.out.println(type.getName());

for (var method : type.getDeclaredMethods()) {
    System.out.println(method.getName());
}

Frameworks such as Spring use class metadata, annotations, reflection and related runtime mechanisms to configure applications and inject dependencies.

These mechanisms also explain why some problems appear at runtime rather than during compilation.

Java Versions

Java has multiple releases, including Java 8, 11, 17, 21 and 25. Newer releases introduce language features, APIs and runtime improvements.

Three versions can matter in a project:

  • Development JDK: the JDK used to compile the application.
  • Target Java version: the release the compiled application is intended to support.
  • Runtime Java version: the version used to execute the application.

A newer JDK can compile code for an older target release using --release, subject to language and API compatibility. 

javac --release 17 Main.java

This targets Java 17 language rules and the documented Java 17 API surface. Third-party dependencies and native libraries must also be compatible with the target environment.

Maven and Gradle

Real-world Java applications usually use build tools rather than compiling every source file manually.

  • Maven: manages dependencies and builds projects using a conventional lifecycle and pom.xml.
  • Gradle: provides a flexible build system configured using build scripts.

Common Java Environment Problems

1. java: command not found

Java may not be installed, or its executable directory may be missing from PATH.

2. javac: command not found

The JDK may not be installed, or the JDK's bin directory may not be available through PATH.

3. Unsupported class file version

The runtime may be too old to load classes compiled for a newer Java release. 

Compiled with newer Java version
             |
             v
Older runtime loads the class
             |
             v
Unsupported class file version

4. ClassNotFoundException

Java cannot find a class that the application attempts to load. Check the classpath, dependencies and class name.

5. Works in the IDE but not in the terminal

Your IDE and terminal may use different JDK installations, environment variables or project configurations.

6. OutOfMemoryError

The JVM may be unable to allocate more memory for a particular operation. Investigate heap usage, object retention, configured memory limits and garbage collection before simply increasing the heap size.

7. Race conditions

Multiple threads may read or modify shared state concurrently. Look for unsafe shared mutable objects, missing synchronization and operations that are assumed to be atomic.

Java vs PHP: Key Differences

Concept Java Typical PHP application
Type system Strong compile-time type checking Type declarations and runtime checks, with different enforcement rules
Execution Compiled to bytecode and executed by the JVM Typically executed through the PHP runtime, often using OPcache
Memory Managed by the JVM and garbage collector Managed by the PHP runtime with request-oriented lifecycles in common deployments
Concurrency Multiple threads can share mutable objects Many conventional PHP-FPM deployments isolate each request in its own worker execution
Generics Compile-time generic types, mostly erased at runtime No equivalent built-in Java-style generic type system
Exceptions Checked and unchecked exceptions No checked-exception requirement
Build tools Maven and Gradle are common Composer is commonly used for dependencies
Deployment Often packaged as a JAR and run on a JVM Often deployed with a PHP runtime and a web server or application server

These are typical deployment patterns, not absolute language limitations. PHP can also run long-lived processes and use concurrency frameworks, while Java applications can be designed around many different execution models.

Important Java Backend Ecosystem Concepts

  • Spring / Spring Boot: application framework, dependency injection, HTTP APIs and configuration.
  • JUnit / Mockito: testing and mocking dependencies.
  • JDBC / JPA / Hibernate: database access, persistence and ORM.
  • SLF4J / Logback: logging APIs and implementations.
  • JVM profiling: diagnosing CPU, memory, garbage collection and thread contention issues.
  • Graceful shutdown: stopping application processes without unnecessarily interrupting active work.

What Should I Remember?

  • The JDK provides tools to develop Java applications; the JVM executes bytecode.
  • Java source code is compiled into bytecode, which a compatible JVM can execute.
  • The JIT compiler can optimize frequently executed code at runtime.
  • JAVA_HOME identifies the JDK installation by convention, while PATH helps locate executables.
  • The classpath tells Java where to find classes and libraries.
  • Java's generic type information is mostly erased at runtime.
  • For objects, == compares references, while equals() can compare logical equality.
  • equals() and hashCode() must follow a consistent contract for hash-based collections.
  • The JVM manages memory, but memory leaks can still occur when unnecessary objects remain reachable.
  • Multiple threads can access shared state, so synchronization and thread safety matter.
  • Streams, lambdas, Optional, records and virtual threads are useful modern Java features to learn.
  • Maven or Gradle, Spring Boot, testing tools and JVM diagnostics are essential parts of many Java backend jobs.
