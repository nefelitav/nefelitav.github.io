Confused Terminology: Networking & Concurrency

6 October 2026

A quick reference for some fundamental networking, operating system and concurrency concepts. The goal is not to explain everything, but to remember what each concept is for and how they differ.

TCP vs UDP

Both are transport-layer protocols. The main difference is the guarantees they provide.

  • TCP — reliable, ordered delivery with retransmissions.
  • UDP — lightweight datagrams without guaranteed delivery or ordering. 
TCP:
"Make sure everything arrives correctly."

UDP:
"Send it quickly; handle loss if necessary."

TCP is commonly used for traditional HTTP traffic, databases and file transfers. UDP is useful for things such as DNS, gaming and real-time communication. Modern protocols such as QUIC can provide reliability on top of UDP.

IPv4 vs IPv6

Both are Internet Protocol versions used to address and route packets between devices.

  • IPv4 — 32-bit addresses such as 192.168.1.10.
  • IPv6 — 128-bit addresses such as 2001:db8::1. 
IPv4 → ~4.3 billion addresses
IPv6 → ~3.4 × 10³⁸ addresses

IPv6 mainly exists because the Internet outgrew the available IPv4 address space.

DNS vs DHCP

Both are network services, but they solve completely different problems.

  • DNS — translates names into network addresses.
  • DHCP — automatically gives devices their network configuration. 
DNS:
google.com → IP address

DHCP:
"Here is your IP, gateway and DNS server."

A device can therefore use DHCP to learn which DNS server to use, and then use DNS to resolve a domain name.

Processes vs Threads

  • Process — a running program with its own isolated memory and resources.
  • Thread — a unit of execution inside a process that shares the process's memory and resources. 
Process
│
├── Thread
├── Thread
└── Thread

Processes provide stronger isolation. Threads are lighter and make it easier to share data, but shared memory introduces synchronization problems.

Concurrency vs Parallelism

  • Concurrency — multiple tasks make progress during overlapping periods of time.
  • Parallelism — multiple tasks execute literally at the same time. 
Concurrency:
Task A ███     ███
Task B     ███     ███

Parallelism:
Core 1: Task A ███████
Core 2: Task B ███████

Concurrency is useful for managing many tasks, especially while some are waiting for I/O. Parallelism uses multiple execution resources to perform work simultaneously.

Race Conditions

A race condition occurs when the result of concurrent operations depends on their timing or execution order. 

counter = 0
Thread A: read → 0
Thread B: read → 0

Thread A: write → 1
Thread B: write → 1

Expected: 2
Actual:   1

Shared mutable state is a common source of race conditions.

Locks, Mutexes & Semaphores

Lock

A lock controls access to a shared resource so concurrent operations do not interfere with each other.

Mutex

A mutex provides mutual exclusion: only one thread can hold it and access the protected resource at a time. 

Mutex
│
├── Thread A → 🔒 access
│
└── Thread B → waits

Semaphore

A semaphore controls access using a number of permits, allowing a limited number of threads to access a resource concurrently. 

Semaphore = 3
Thread A → permit
Thread B → permit
Thread C → permit
Thread D → waits

A simple way to remember the difference:

  • Mutex → one at a time.
  • Semaphore → up to N at a time.

Deadlocks

A deadlock occurs when concurrent operations wait for each other indefinitely, so none of them can continue. 

Thread A                  Thread B
│                         │
locks A                   locks B
│                         │
waits for B               waits for A
│                         │
└───────── DEADLOCK ──────┘

Locks can prevent race conditions, but incorrect locking can introduce deadlocks.

How DNS Works

DNS is a distributed naming system that resolves domain names into IP addresses. 

Browser
↓
DNS Resolver
↓
Root
↓
TLD (.com)
↓
Authoritative DNS
↓
IP address

In practice, results are often cached, so the entire lookup does not need to happen every time.

How HTTPS Works

HTTPS = HTTP + TLS.

TLS provides encryption, integrity and authentication for HTTP communication. 

Client
│
│ TLS handshake
▼
Server
│
│ encrypted connection
▼
HTTP request / response

During the TLS handshake, the server presents a certificate, the client verifies it, and both sides establish cryptographic keys for the connection.

How They Fit Together

These concepts are different layers of the same overall process. 

https://example.com

  DNS

Meanwhile, inside the operating system and applications, processes and threads execute the work, while concurrency, parallelism, locks and synchronization determine how that work happens safely and efficiently.

What Should I Remember?

  • TCP → reliable and ordered transport.
  • UDP → lightweight transport without delivery guarantees.
  • IPv4 → 32-bit addressing.
  • IPv6 → 128-bit addressing and a vastly larger address space.
  • DNS → names to IP addresses.
  • DHCP → gives devices their network configuration.
  • Process → isolated running program.
  • Thread → execution unit inside a process.
  • Concurrency → multiple tasks making progress.
  • Parallelism → multiple tasks executing simultaneously.
  • Race condition → result depends on timing/order.
  • Lock / Mutex → controls exclusive access to shared state.
  • Semaphore → limits concurrent access to N operations.
  • Deadlock → tasks wait for each other indefinitely.
  • HTTPS → HTTP secured with TLS.
